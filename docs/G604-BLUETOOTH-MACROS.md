# G604 蓝牙宏工具（Windows 开发版）

这个版本直接扩展 OpenLogi。宏库、时间线和绑定在桌面界面编辑，键盘捕获、宏回放和 G604 板载配置由 agent 负责。

当前已完成代码实现和 Windows 构建。2026-10-05 的实机日志确认六个实体侧键槽位校准及板载配置写入、读回校验成功；随后检查时，六键输出验证为 0/6，宏接入尚未启用。F13–F18 实体输出、实体键盘录制和蓝牙断开仍未完成验收。不要把写入成功或界面“测试输入”成功等同于实体鼠标触发成功。

## 公开源码与编译

公开 fork：<https://github.com/inspirai-store/OpenLogi>，功能分支为 `feat/g604-bluetooth-macros`。

Windows x64 编译需要 Git、Rust 1.98.0、Visual Studio C++ Build Tools 和 Windows SDK。在源码根目录运行：

```powershell
rustup toolchain install 1.98.0 --component rustfmt --component clippy
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/g604-macros/build.ps1
```

脚本从已提交且无改动的源码编译 Release 版 desktop、agent、overlay 和恢复工具，输出到 `target/packages/`。便携目录及 ZIP 包包含启动器、恢复入口、许可证、说明、源码提交编号和 SHA-256 校验值。也可用 `-OutputDirectory` 指定输出父目录。编译不启动程序或修改鼠标配置。

## 启动与配置位置

开发包内的 desktop、agent、overlay 使用相同版本（0.8.11）和 IPC 35。双击 `start.cmd`（早期开发包中名为 `启动宏工具.cmd`）；启动器使用独立的 `OPENLOGI_PROFILE=dev` 配置。

- 配置：`%USERPROFILE%\.config\openlogi-dev\config.toml`。
- 接管期间的原始恢复记录：同目录下 `g604-recovery.json`。
- 已验证的实体键映射：同目录下 `g604-calibration.json`。

正常关闭桌面窗口只关闭编辑器，agent 继续运行。需要停止鼠标接管时，点击宏页面的“停用并恢复原配置”；退出整个套件使用 OpenLogi 托盘菜单的退出项。原始恢复记录只会在设备读回恢复成功后移除。

如果存在另一份开发版本的 agent，先从旧版本正常退出，或先恢复鼠标配置再停止旧进程。启动器不会自动强制终止其他版本的 agent。

## 首次设置 G604

1. 连接当前 G604 蓝牙设备，移动鼠标使它保持唤醒，进入设备的“宏”页面。
2. 点击“备份并开始校准”。agent 在切换模式前保存原始目录、活动配置、备用配置、模式、配置编号和当前 DPI。
3. 点击 G4，然后实际按下对应的实体侧键。出现 ✓ 后依次完成 G5～G9；同一个协议槽位不能分配给两个实体键。
4. 六键校准完成后，点击“写入 F13–F18 触发键”。只有原来禁用的板载配置 2 可以作为备用配置。写入前核对描述符、配置目录和备用扇区；写入后读回验证 CRC、完整内容及 DPI。
5. 依次点击 G4 → F13 至 G9 → F18，并实际按下对应侧键。任何键输出不符合预期时，agent 自动尝试恢复原配置并禁用触发接入；恢复失败时保留恢复记录和错误原因。
6. 六键都通过后点击“启用已验证的触发键”。成功验证的校准映射会单独保存，后续原配置和设备身份匹配时可以复用映射。

启用期间，F13–F18 是系统保留触发键：其他键盘的这六个键也会被拦截。普通数字、标点及其他键保持原有输入路径。复杂宏由电脑执行，板载配置只负责产生专用触发键。

## 宏库和时间线

“新建宏”默认生成单次 `12345`，按住与按键间隔为 50 毫秒。编辑名称后保存；“复制”创建独立副本，“删除”同时清除配置中对该宏的引用。

每个宏有开始、循环、结束三个阶段。选择动作后可修改扫描码、E0 标志、鼠标按钮、滚轮量或延迟，也可以插入、复制、删除、上移和下移。时间线每页最多显示 40 个动作。

“修改按住时长”修改选中按下动作与对应松开动作之间的延迟；“统一延迟”修改已有延迟以及循环间隔。想只插入按下或松开边沿，可以先插入完整按键动作，再删除不需要的边沿。

| 模式 | 触发及停止方式 |
| --- | --- |
| 执行一次 | 完整执行一次，运行时忽略重复按下 |
| 指定次数 | 循环阶段执行指定次数，运行时忽略重复按下 |
| 按住循环 | 按下开始，松开进入结束阶段 |
| 开关循环 | 第一次按下开始，下一次按下进入结束阶段 |
| 分段执行 | 按下执行开始阶段，保持时重复循环阶段，松开执行一次结束阶段 |

开始和结束阶段也适用于单次、指定次数和开关模式。例如在开始阶段按住右键，循环阶段执行数字键，结束阶段松开右键。

允许不同绑定并行；每个绑定最多一个运行实例。同一个键由所有运行实例共同持有，最后一个持有者退出时才松开。重叠的同键动作可能合并。

## 录制和应用绑定

点击“开始录制”后实际输入按键，或在目标窗口点击鼠标、滚动。录制保留按下、松开和真实时间间隔；不录制移动轨迹。注入事件不会再次录入；工具界面上的鼠标操作不会录入，以免停止录制按钮被回放。

停止录制后，动作进入当前选择的阶段，先检查、编辑，再保存。录制器会忽略自动重复的按下和没有对应按下的松开，缺失的松开事件由录制结束和执行器清理兜底。

在页面上方选择默认配置或添加应用配置，再点击“绑定 G4”至“绑定 G9”。绑定保存到当前设备和当前选择的应用配置；执行时沿用 OpenLogi 的前台程序匹配规则。

运行状态显示当前前台应用和正在运行的宏。“停止全部”立即取消所有宏；紧急停止默认 `Ctrl+Alt+F12`，可在界面修改并保存。界面中 `control+option+f12` 是内部快捷键文本，在 Windows 上对应 Ctrl+Alt+F12。

普通松开会执行结束阶段。紧急停止、窗口切换、蓝牙断开和 agent 退出会立即取消并清理已持有输入，跳过用户配置的结束阶段，避免长延迟拖延停止。

## 导入和导出

JSON 导出当前编辑的宏，导入接受单个宏定义；导入文件大小限制为 16 MB。导入的宏先加载为编辑草稿，检查后保存。

“导入 G HUB”以只读方式访问当前用户的 `LGHUB/settings.db`，列出宏名和动作数量。点击预览项后可以检查时间线；不支持的动作会显示原始内容，不能当作已完整转换。G HUB 的脚本等动作没有自动执行路径。

当前 G HUB 的“一键宏”能读出 21 个动作，其中缺少最终右键松开事件；执行器会在停止或结束时释放该宏持有的输入。

## 12345 验收

点击“测试输入”后，界面把焦点放到测试框，1.5 秒后开始回放。单次应得到 `12345`；指定次数为 3 时应得到 `123451234512345`。按住和分段模式的预览用“松开触发”结束；“停止全部”直接取消。

已实际验证：真实 Windows OpenLogi 测试框的单次、三次重复和按住后停止；界面保存与 G4 绑定写入配置；G HUB 只读预览；两个宏和 HoldShortcut 共同持有 F13 时，逐个释放不会提前松开；接管校准前的硬件备份及通过 agent IPC 恢复原模式、配置与 DPI。

待实机验证：实体键盘录制、完整编辑与重启重载、六侧键校准、F13–F18 实际输出、实体侧键触发、写入后恢复、蓝牙断开、正常退出恢复。分段顺序、延迟中取消、有限次数、共享持有和旧配置迁移已通过逻辑测试，不能替代这些实机项目。

异常退出后，agent 读到 `g604-recovery.json` 会要求先恢复，不能直接开始另一轮接管。恢复时核对同一物理设备、扇区几何和 CRC，读回原配置、模式、配置编号和 DPI；设备断开或恢复失败时保留记录。

界面不可用但 agent 仍运行时，开发包的 `restore.cmd`（早期开发包中名为 `恢复原配置.cmd`）可通过 IPC 请求恢复。开发仓库也提供同一恢复例子：

```powershell
$env:OPENLOGI_PROFILE = 'dev'
cargo +1.98.0 run -p openlogi-agent --example g604_recovery -- status
cargo +1.98.0 run -p openlogi-agent --example g604_recovery -- restore
```

这些命令依赖正在运行且协议兼容的 agent，不直接访问 HID，也不生成键盘输入。不要手工删除恢复记录来跳过恢复。
